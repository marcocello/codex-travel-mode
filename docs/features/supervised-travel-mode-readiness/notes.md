## 2026-07-17 Contract Repair 2
- This is an explicit contract-repair state. The previous repaired contract was still wrong in four completion-relevant ways: it implied exact prior-SSID recovery gated Off/Quit, attributed Quit ordering causality to the live harness, allowed one controller to author its own system facts, and left critical provider/helper/arming bytes and identities underspecified.
- Upstream behavior is unchanged. Prior-SSID reassociation remains bounded best effort and does not gate Off or Quit. A successful supervised acceptance run still requires exact final prior-SSID equality; a mismatch makes this live run non-acceptable without proving a product policy violation.
- AppKit termination causality and internal join count are delegated to the safe-menu and handoff dependency proofs. Live proof observes manual production Quit, mandatory power/journal cleanup, and exact external process ordering only.
- The harness now has a cryptographic controller/observer split. One long-lived exact-hash observer generates an in-memory ephemeral Ed25519 key, binds its public key/PID/start/hash into arming, and owns a private mode-`0600` AF_UNIX socket under the mode-`0700` output directory. It accepts exactly a same-UID/hash-bound preflight session and one HMAC-authenticated live attach, signs both phase/PID/start/sequence handshakes, preserves one event chain, and rejects every extra or reset attach. It exclusively owns system, network, process, dynamic-helper SecCode, registration, journal-presence, HTTPS transport, TaskMetrics, and provider-receipt-copy facts. The controller records arming, orchestration, operator actions, typed requests, and cleanup requests only.
- Arming is five-minute HMAC-SHA256 state with a random 256-bit sidecar secret, challenge digest only, and atomic one-time consumption. Consumption atomically unlinks the sidecar and zeroizes its in-memory buffer; it does not make an unverifiable disk-zeroization claim. Raw evidence is sealed mode `0400`, hashed, and reverified; proof-capture paths are role-redacted.
- Provider v1 now fixes config/capability/submit/readback schemas, query encoding, 32-byte key, 64-byte signature, NUL-separated canonical signed bytes, exact `1...N` sequences, capability-bounded clock skew, two-second observation adjacency, TaskMetrics address binding, exact-remote route checks, and five-second/64-KiB transport limits without redirect/cookie/proxy behavior.
- Helper readiness now checks the dynamic running PID with SecCode identifier/team/CDHash/path equality against the embedded enabled helper. Root journal presence requires an exact NOPASSWD fixed existence query; ordinary sudo cache is not readiness and unauthorized is never interpreted as absent.
- Production Location is verified after each fresh exact app launch. AX trust belongs to the observing harness, not the production app. Every scenario starts with no app and uses a fresh PID/start identity.
- Failed/interrupted cleanup may use exact-process `NSRunningApplication.terminate`, and emergency rescue remains available, but either permanently invalidates PASS.
