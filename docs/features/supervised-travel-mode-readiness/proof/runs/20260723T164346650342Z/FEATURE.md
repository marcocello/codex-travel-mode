# Supervised Travel Mode readiness harness

## Summary
Provide a guarded live acceptance workflow that proves, on one recorded Mac/macOS/operator-attested-iPhone combination, that the exact signed packaged app has outbound connectivity over the configured target while closed on battery and restores its mandatory owned state after Stop, Quit, and unexpected app-owner death.

## Safety And Operator Boundary
- Execution has two phases. Default `--preflight` performs no app launch, helper registration, heartbeat submission, power/Wi-Fi mutation, journal cleanup, or process termination. It may create private evidence files, run fixed read-only probes, and call the provider capability endpoint.
- Preflight creates a five-minute arming receipt bound to run ID, machine, baseline, controller hash, observer public key/PID/start identity/executable hash, signed app/helper identity, provider origin, and output directory. A random 256-bit sidecar secret mode `0600` authenticates the receipt with HMAC-SHA256. The receipt stores only the challenge digest; the challenge is displayed once and entered from a controlling TTY. After successful verification, live mode atomically creates a one-time `O_EXCL` consumption marker before any live action, atomically unlinks the sidecar, and zeroizes only its in-memory secret buffer. Environment flags cannot arm live mode.
- The operator keeps the Mac supervised, ventilated, unenclosed, on battery, and manually uses the production Start, `Stop & Restore`, Quit, and relaunch controls. The harness never calls app internals or proof-only selectors.
- Normal owner death alone uses `SIGKILL` against the recorded exact app PID plus process-start identity. Name-based killing is forbidden. During failed or interrupted cleanup only, the controller may call `NSRunningApplication.terminate` for that same revalidated PID/start identity; this safety action permanently makes the run non-PASS.
- Each closed interval needs at least ten seconds of healthy observations and has a 90-second hard deadline from the first authoritative closed sample. Timeout, signal, terminal loss, observer/controller death, evidence failure, or incomplete observation enters cleanup and blocks later scenarios.

## Split Trust Boundary
- A controller owns prompts, arming, orchestration, manual-action requests, and safety-cleanup requests. For heartbeat it may request only a closed typed `capability|submit|readback` action; it never opens provider connections or receives TaskMetrics. It writes command, operator, and cleanup-request facts only and cannot author system, network, provider-transport, process, helper, or journal observations.
- One long-lived separate observer process generates an ephemeral Ed25519 key in memory before preflight. Its raw 32-byte public key, exact PID/start identity, and executable SHA-256 are bound into preflight and arming; its private key is never persisted or shared. The same observer process/key/event chain must remain alive through final sealing and may accept exactly two controller sessions: preflight and one live attach.
- The observer owns one AF_UNIX socket mode `0600` inside the mode-`0700` output directory. It accepts only same-UID peers whose executable hash equals the controller hash bound at preflight. It signs distinct `preflight` and `live` handshakes containing run ID, phase, client PID/start identity, controller hash, and the request-sequence starting point; live continues the monotonic sequence and cannot reset it. The live attach additionally proves the HMAC receipt/sidecar and atomically consumes the one-time marker before any live action. Unauthenticated, concurrent, third, post-live, hash-mismatched, wrong-UID, sequence-reset, or differently phased attaches are permanently non-PASS.
- The observer owns lid, battery, `pmset`, Wi-Fi, route, process, code-identity, helper-registration, journal-presence, HTTPS capability/submit/readback, URLSessionTaskMetrics, and provider-transport observations. Every observer event is an envelope containing the exact persisted UTF-8 payload bytes as base64url, its previous-envelope SHA-256, and an Ed25519 signature over ASCII `codex-travel-mode-observer-event/v1`, one NUL, then those exact payload bytes. Handshake and final-seal signatures use the same construction with domain strings `codex-travel-mode-observer-handshake/v1` and `codex-travel-mode-observer-seal/v1`. It copies provider-signed receipts unchanged, performs no system mutation, and writes `observer-events.json`, `provider-transport-events.json`, and `provider-receipts.json` independently.
- Every scenario uses a fresh exact app process. Preflight and each scenario boundary require no pre-existing app; Stop is followed by a manual clean-Off Quit before the next scenario. PIDs, start identities, executable hashes, controller PID, observer PID, and oracle PID must be distinct and cross-referenced.
- Raw files are fsynced, closed, chmod `0400`, hashed into a seal manifest, and rehashed before and after the independent oracle. The still-running observer writes `observer-seal.json` whose signed exact payload binds its process identity, public key, event count, final chain hash, and every observer-owned file hash; it exits only after that seal is durable. Absolute home, configuration, output, and app paths are replaced in captured commands/logs by role labels plus digests.

## Clean Baseline And Signed Runtime
- The anchored run baseline has `SleepDisabled=0`, selected Wi-Fi powered on, a non-empty prior SSID whose exact UTF-8 bytes differ from the configured target, both active journals absent, and no app process. Each later scenario must match it before Start.
- Mandatory state that gates verified Off/Quit is the exact `SleepDisabled` baseline, exact Wi-Fi power baseline, and absence of active app/helper journals. Prior-SSID reassociation remains the upstream product's bounded best-effort policy: successful live acceptance additionally requires exact prior-SSID equality, but a mismatch does not gate Off/Quit and this proof must not claim failure-policy causality. Addresses and routes are semantic, never byte-restoration fields.
- Every authoritative sample from Start through cleanup must report Battery Power; an AC sample invalidates the scenario. Preflight requires a supported portable Mac and at least 20 percent charge.
- The target must byte-match the committed production configuration, have a saved Keychain credential without reading its value, be visible, differ from the prior SSID, and be operator-attested as the intended iPhone. Codex must be running.
- The harness's own AX trust is a separate readiness prerequisite used only to observe production UI state and manual actions. The production app needs no Accessibility grant. After each exact app launch and before Start, the production app's Location authorization and committed configuration are verified through its read-only production UI/discovery state; no permission request occurs during proof.
- The app must be Developer-signed as `com.codex.travelmode`. The embedded helper must be `com.codex.travelmode.sleep-helper` with the same non-empty Team Identifier and valid reciprocal requirement. `SMAppService` must already be enabled. Before every scenario and after any helper PID change, the observer resolves the dynamic running helper PID and uses SecCode to require identifier, Team Identifier, CDHash, and executable path to match the embedded helper exactly.
- Helper-journal observation requires an exact NOPASSWD sudoers grant for `/usr/bin/test -e /Library/Application Support/com.codex.travelmode/SleepOverrideLease/active-lease.json`. Before each query the observer uses fixed `sudo -n -l` authorization read-back, then the fixed `sudo -n` query; exit `0` means present and exit `1` means absent only while authorization remains confirmed. Unauthorized, cached-password-only, changed command, or indeterminate output is distinct from absent and blocks proof. Journal contents are never read.

## Versioned HTTPS Heartbeat Protocol
- Observer-consumed provider config schema `codex-travel-mode-provider-config/v1` contains one public HTTPS origin, capability/submit/readback paths without query or fragment, a base64url-no-padding Ed25519 raw public key decoding to exactly 32 bytes, and optional Keychain `service` plus `account` together. If configured, the UTF-8 Keychain value is sent only as `Authorization: Bearer`; header/token files are forbidden.
- Requests use an ephemeral URLSession, platform TLS, no redirects, cookies, cache, credential persistence, or proxy, with a five-second timeout and 64-KiB response limit. Capability schema `codex-travel-mode-heartbeat-capability/v1` returns protocol `codex-travel-mode-heartbeat/v1`, exact configured paths, server Unix milliseconds, and maximum clock skew `0...30` seconds. Midpoint-derived absolute skew must not exceed both the advertised value and 30 seconds.
- Each submit body uses schema `codex-travel-mode-heartbeat-submit/v1`, lowercase canonical UUID run ID, scenario enum `stop|quit|owner_death`, integer sequence, a fresh base64url-no-padding 32-byte nonce, and Unix milliseconds. Readback uses only percent-encoded `run_id` and `scenario` query items created by URLComponents; duplicate or additional query items are forbidden.
- Readback schema `codex-travel-mode-heartbeat-readback/v1` returns receipts in exact sequence `1...N`, with no gaps or duplicates. A receipt has schema `codex-travel-mode-heartbeat-receipt/v1`, the exact run/scenario/sequence/nonce, server receive milliseconds, source family `ipv4|ipv6`, source address as base64url raw 4/16 bytes, and a base64url Ed25519 signature decoding to exactly 64 bytes.
- The signed bytes are ASCII prefix `codex-travel-mode-heartbeat/v1`, then NUL, then in order the canonical run ID, scenario, base-10 sequence without leading zeros, nonce, receive milliseconds without leading zeros, source family, and source-address value, separated by single NUL bytes with no terminal NUL. The oracle reconstructs these bytes and verifies Ed25519, uniqueness, exact sequence, clock-adjusted closed-window receipt times, and nonce binding.
- URLSessionTaskMetrics must expose the actual local and remote addresses for every submit. Within two seconds before dispatch and two seconds after completion, observer samples must show lid closed, Battery Power, exact target digest, a usable selected-interface address, and route lookup to that exact public remote address using the selected Wi-Fi device. The task local address must be one of those interface addresses. Provider-observed source is evidence of public egress, not proof of iPhone hardware identity.
- At least three valid receipts must span ten seconds. Live observation requires no externally observed disconnect/reassociation after target health. Internal join count remains owned by the deterministic handoff dependency proof.

## Scenarios
- Stop: fresh launch, post-launch Location/config verification, manual Start, physical close, heartbeat sequence, reopen, manual `Stop & Restore`, mandatory Off cleanup, then exact prior-SSID acceptance comparison and manual clean-Off Quit.
- Quit: repeat fresh, reopen, manually invoke production Quit, observe mandatory power/journal cleanup and exact process-exit ordering, then separately compare prior SSID for live acceptance. The dependency lifecycle proof owns AppKit termination causality.
- Owner death: repeat fresh through closed heartbeat, exact-PID/start `SIGKILL`, reopen if sleeping, require app absent, mandatory sleep restoration, helper active journal absent, and app journal retained; manually relaunch for production recovery, require mandatory cleanup plus exact prior SSID for acceptance, then manual clean-Off Quit.
- Failure or interruption: seal all facts, request cleanup only through production Stop/Quit/startup recovery or helper owner-death paths, and never continue. Exact-process `NSRunningApplication.terminate` or explicit direct rescue is safety-only and permanently non-PASS.

## Evidence And Completion
- Raw artifacts are `preflight-readback.json`, `arming-receipt.json`, `command-events.json`, `operator-events.json`, `cleanup-events.json`, observer-owned `provider-transport-events.json`, `provider-receipts.json`, `observer-events.json`, `observer-seal.json`, and `seal-manifest.json`. They contain facts only and forbid `pass`, `passed`, `verdict`, `checks`, `assertions`, `expected`, `matches`, and equivalent derived-success keys.
- One separate exact-hash oracle process consumes sealed artifacts, validates strict schemas/authorship/sequences/hashes/signatures/timing/redaction, and alone writes `oracle-report.json`. The controller cannot evaluate its own run.
- SSIDs, interface/source addresses, machine/account identity, and paths are stored as per-run salted digests or bounded classifications unless plaintext is essential. Passwords, administrator credentials, Keychain values, authorization headers, raw process arguments/environments, unrelated processes, and raw journals are never captured.
- `scripts/run_live_travel_mode_proof --preflight` emits the sealed readiness facts and arming material. `--live --receipt` revalidates and consumes them. Zero exit requires the independent oracle to accept every scenario; deterministic tests, readiness, retained failure evidence, or rescue never complete the live feature.

## Non-Goals And Resolution
- The proof does not automate lid or normal UI controls, redefine upstream best-effort SSID recovery, prove AppKit causality, count internal join calls, identify an SSID cryptographically as an iPhone, certify unattended/enclosed use, or cover every platform combination.
- Physical/system/provider/observer read-back outranks app text. Missing, stale, replayed, unsealed, unreadable, or ambiguous evidence is non-PASS.
- Required skills: coding-feature-execute, coding-proof-author, coding-feature-quality
